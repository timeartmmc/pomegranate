# Contributing

Use Node.js 24.x and npm. Install the locked development dependencies, then run
the complete verification command from the repository root:

```sh
npm ci
npm run verify
```

`verify` checks formatting and lint, builds the package, runs the compiler and
runtime tests, checks and runs the synthetic example, and exercises a packed
install in an isolated consumer. The installed-package check must not rely on a
sibling checkout or a source symlink. Keep CI and this command aligned.

Strict TypeScript checks the compiler and dependency declarations. Oxlint adds
type-aware checks for compiler and example TypeScript, including unsafe values,
Promise misuse, and exhaustiveness. Dynamic JavaScript tests and scripts receive
syntax and correctness checks; they are not a type-checked TypeScript program.
Generated modules and intentional negative type fixtures are excluded from lint
and checked through actual consumer compilation.

Use Oxlint for JavaScript/TypeScript linting and Oxfmt for supported-file
formatting. Keep both enforced by `npm run verify`, preserving the check scopes
above when changing tooling. The pinned Oxfmt API owns generated bytes through
explicit compiler options, independent of consumer formatter configuration.
Generated clients do not import the formatter.

`test/schema-oracle.test.mjs` compares emitted request and response validators
with Ajv2020 on selected supported schema cases. Ajv is a development dependency;
generated code uses Zod.

## Make a change

Read [architecture and requirements](ARCHITECTURE.md) before changing contract
interpretation or generated behavior. Change generated files through their
owning input or emitter. For the synthetic example:

```sh
npm run build
npm run example:generate
npm run example:check
npm run example:run
```

Review the generated diff. Run `npm run format` for human-authored source and
documentation as needed, then run `npm run verify`. Tests import the built
package; rebuild before a focused `npm test` after changing source.

Add tests for observable behavior and meaningful failure paths. A new schema or
protocol feature needs positive coverage, a rejected neighboring form, agreement
between emitted types and validators, and an installed-consumer check when it
changes the public API. Output changes need drift and ownership tests. Avoid
tests that only repeat emitter text.

Use synthetic public fixtures. Application repositories own real schemas,
exporters, scalar corpora, transports, and integration checks. A compiler test
does not establish that an application integration is ready.

## Before publication

The package is private and unpublished. Its name and license remain provisional.
The initial standalone implementation uses earlier application-specific compilers
as behavioral references; its source modules are newly authored. Preserve
accurate source provenance and any required notices when publishing.

Inspect the actual `npm pack` inventory before publication. Keep application
contracts, private repository history, credentials, environment files, local
paths, and coordination state out of the public repository and distribution.
If reusable source is adapted, preserve the notices its license requires.
