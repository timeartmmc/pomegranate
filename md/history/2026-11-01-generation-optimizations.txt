POM GENERATION OPTIMIZATIONS — 2026-11-01

Dated local evidence for the three adopted optimization proposals. Current
behavior belongs to ARCHITECTURE.md and QUERIES.md; initializer/import/cache
rationale lives beside the owning compiler code. Other generation proposals
remain decisions or separate capability milestones.

Baseline: checkout 90955119d8551b9a00cbd267813cabfa62a92ec3 (0.3.0).
Measurements: Node 26.12.1, Zod 4.6.7, esbuild 0.27.7, browser ESM,
ES2022, minification, Node default gzip. Synthetic inputs only; these results
establish no application, device, or production performance result.

Terminal alias resolution

For 10,000 forward aliases ending in a string, three-run local medians:

Selection                Baseline       Cache only
Leaf only                1,059.38 ms        18.67 ms
Whole alias chain        2,045.28 ms        41.58 ms

Six complete output maps were byte-identical after the cache-only change:
example, schema/standalone, browser/native multipart, execution, cursor queries,
and offset queries. The cache stores terminal schemas by normalized table and
reference node. Contextual validation still visits intermediate constraints and
defaults. Deterministic lookup-count coverage establishes linear shared-chain
resolution without a timing threshold. Tests also cover reused reference nodes
across tables, repeated compilation of mutable inputs, specialized array
validators, exact missing-reference/cycle diagnostics, and contextual defaults.
No ordinary-contract timing improvement is claimed.

The import-only control reduces gzip by about 66% on the four-operation fixture.
The sparse change reduces gzip by about 55% against the namespace-only control
with 500 extra operations. Generated source increases from 1,840,954 to 2,058,955
bytes in that case: named declarations and initializer boundaries trade source
size for removable unused construction. Full client consumers retain their full
operation set. These fixtures differ from the original proposal measurements;
the original exact byte counts are not asserted as a universal result.

Revalidation and regression coverage

test/bundle.test.ts compares namespace/named Zod imports with complete schema
acceptance checks, then checks sparse/full ordinary queries, cursor and offset
queries in envelope/body modes, shared alias/operation instances, frozen
aggregates, and browser/native multipart with esbuild and Bun. Added unused
contracts must disappear from sparse bundles while full aggregates retain and
validate all 100 added operations. The canonical checks also own declarations,
minimum peers, browser execution, output ownership, and packed execution after
compiler removal. CONTRIBUTING.md owns their commands and required coverage.
