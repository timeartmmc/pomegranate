1. Brackets around every key

   Accurate. Ordinary keys can use label:, and names containing punctuation

3. Repeated string-length lambdas

   Accurate, with a simpler alternative available. Native .min() and .max()
   already count Unicode code points in both the minimum supported Zod 4.6.6
   and installed Zod 4.6.7. This was verified with BMP characters, emoji,
   combining marks, a lone surrogate, and an empty string.

   Therefore, z.string().min(1).max(40) preserves the relevant length
   acceptance semantics without introducing a codePoints() helper. POM's
   comment saying native bounds count UTF-16 is stale for its current peer
   minimum. Existing message text can be supplied explicitly, although raw
   Zod issue codes would change.

   node_modules/zod/src/v4/core/checks.ts:561

Regex evaluation after a length failure

The observation is correct. Instrumented refinement chains on Zod 4.6.6 and
4.6.7 each ran the regex once for a four-code-point string that failed a
maximum length of two.

Fixing this requires explicit short-circuiting, such as a pipeline or an
early return inside a helper. Merely extracting the existing refinements,
or placing the regex after a length refinement, does not fix it. Skipping
checks can also change the collection of reported issues while preserving
which values are accepted.

A string helper cannot itself remove redundant boolean or numeric literal
checks. Literal simplification requires a separate emitter change.

Sources: src/emit-schema.ts:29, src/runtime.ts:26

Deliberate structure to preserve

Named structural validator types limit inference expansion through schema
references. Arrays retain the specialized ZodArray API so reference sibling
bounds can reject oversized arrays before validating their items.

The _part declarations keep aggregate expressions shallow for the formatter
and TypeScript. Relaxing them for tiny schemas is a tradeoff, not an obvious
correctness fix.

Sources: src/schema-types.ts:74, src/emit-schema.ts

Impact and verification limits

The readability and generated-diff benefits are clear. Claims about
meaningful bundle-size or speed improvements still need measurement against
bundled and compressed output. Type import cleanup has no runtime effect.
